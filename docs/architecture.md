# CrossW — архитектура

Статус: рабочая версия, 2026-09-10. Что за продукт — в [spec.md](spec.md).

## 1. Слои

Зависимости идут строго в одну сторону, обратных нет.

```
src/app, src/components, src/hooks      React, DOM, Next
  рендерят состояние, зовут движок           │  игровой логики нет
                                             ▼
src/engine                              чистые функции, ноль React
  PlayState → PlayState: курсор, ввод,        │  индекс «клетка → слова»
  проверка, подсказка, прогресс               ▼
src/core                                типы и правила, ноль зависимостей
  разбор сетки, нумерация, компиляция, обфускация, валидатор

Сборка контента идёт мимо приложения:
content/*.json → tools/build-content.ts → public/p/<id>.json  (без букв)
   (git, буквы)     (node:fs только тут)     public/p/<id>.sol  (решение)
```

`node:fs` разрешён только в `tools/`. Поэтому `core` и `engine` тестируются вызовом
функции — без jsdom, без моков.

## 2. Три правила

**2.1. В компонентах нет игровой логики.** Компонент рендерит `PlayState` и зовёт функцию
движка. Нужно узнать, каким словам принадлежит клетка — спрашивает индекс.

*Прошлый прототип нарушал это в каждом обработчике и кончил компонентом на 346 строк, где
проверка ответа искала слово линейным `.find()` прямо из JSX.*

**2.2. Нумерация вычисляется, а не хранится.** Сквозная нумерация — функция от сетки
(`core/grid.ts`). В JSON кроссворда номеров нет.

*В прототипе номера лежали в JSON, и существовало два разных слова №1 — по горизонтали и по
вертикали. Баг был не в функции, а в том, что источников правды стало два.*

**2.3. Ответы не уезжают в браузер открытым текстом.** `content/` хранит сетку с буквами —
её видно в диффе и можно проверить глазами. На сборке решение вынимается в `<id>.sol`
с XOR-обфускацией, в `<id>.json` не остаётся ни одной буквы ответа.

*Это защита от «посмотреть исходник», не криптография: ключ выведен из id и лежит в том же
бандле. Игра идёт на клиенте, спрятать от него ответы невозможно.*

## 4. Форматы данных

| | source | compiled |
|---|---|---|
| Где | `content/puzzles/<id>.json` | `public/p/<id>.json` + `<id>.sol` |
| Для кого | человек на ревью | плеер в браузере |
| В git | да | нет, собирается |
| Сетка | строки с буквами, `#` — блок | плоский массив: `-1` блок, `0` клетка, `>0` номер |
| Слова | ключи `"1A"`, `"3D"` → текст | `CompiledEntry` с плоскими индексами клеток |
| Ответы | видны | вынесены в `.sol` |

**Почему `cells` — плоские индексы.** «Следующая буква» это `cells[k + 1]`, а не «строка та
же, колонка +1» для горизонтали и наоборот для вертикали: у ввода, проверки и подсказки по
одной ветке кода вместо двух.

Важнее второе следствие: клетка на пересечении — **один и тот же индекс** в `cells` обоих
слов, буква хранится один раз. Расхождение букв между пересекающимися словами невозможно
физически, сверять нечего.

`dir` остаётся только для интерфейса: список делится на «По горизонтали» и «По вертикали».

## 5. Генератор

Слова кладутся жадно: первое — в середину, каждое следующее цепляется буквой к уже стоящему.
Блоки получаются из незанятых клеток. Такой генератор не может не сойтись — он просто
останавливается, когда больше ничего не влезает.

Корректность проверяется не рассуждением о соседствах, а разбором готовой сетки: **каждое
слово в ней обязано быть словом из пака.** Одно условие закрывает и случайные двухбуквенные
слова, и сочетания, приклеившиеся сбоку.

Порядок очереди определяет результат: сначала свежие слова с тематическим определением
(порог 60% из spec §5.8), потом остальные, потом уже потраченные на другие сетки темы.

Плата за простоту — разреженные сетки: пересечений 22–29% вместо 50% у журнального
кроссворда. Плотная сетка требует словаря филлеров, которого пока нет.

## 6. Стек и команды

Node 22 · Next.js 15 App Router, `output: 'export'` · TypeScript strict
с `noUncheckedIndexedAccess` · Tailwind · vitest.

```bash
npm run dev        npm test           npm run validate
npm run content    npm run build      npm run gen
```

Сайт статический целиком: ни сервера, ни базы. Отсюда и отсутствие аккаунтов, и то, что
ответы принципиально на клиенте.

### Чего сознательно нет

| Не берём | Почему |
|---|---|
| Монорепо с пакетами | границы держатся направлением импортов, а не `package.json` |
| zod | единственный вход недоверенных данных — свой же `content/`, его проверяет валидатор по правилам ТЗ, а не по форме типов |
| CI | один разработчик; `npm test && npm run validate` делает то же без YAML |
| Playwright | вся игровая логика в `engine/` и покрыта юнит-тестами без DOM |
| Lighthouse | статика без картинок и сторонних скриптов, мерить нечего |

При одном разработчике обвязка стоит дороже того, что ловит. Чистота архитектуры здесь стоит
ноль строк — она в направлении зависимостей.
