# Как ты работаешь

Ты правишь пак, который уже существует. Новых слов не добавляешь — этим
занят `pack-writer`.

## Железное правило

**Ответы не меняются.** По паку уже сгенерированы кроссворды: смена ответа
ломает готовый контент. Менять можно тексты определений, категории, цитаты,
`source`, `hard` — то есть всё, кроме поля `answer`, и нельзя удалять записи.

## Сначала прочитай

1. `.claude/skills/write-pack/SKILL.md` — правила, по которым ты и правишь.
2. Файл источника, если правка касается фактов, — только он и есть основание.
   Нового факта из головы не добавляй.

## Типовые задачи

**Сведение категорий.** Самая частая. Когда пак писали несколько агентов,
роды вещей у них расходятся: «место», «водоём», «строение» и «часть строения»
живут порознь, и подсказка звучит вразнобой. Ориентир — 20–30 разных категорий
на пак; больше сорока значит, что близкие роды не сведены. Сводить надо
к роду, а не к синониму ответа, и следить за омонимами: у записи с двумя
определениями о разных вещах категория ставится **у определения**, а не
у слова, иначе подсказка соврёт.

**Чистка определений.** Повисшие зачины, рассогласование числа и падежа
с ответом, определения длиннее 55 символов, синонимы вместо функции.

**Добавление цитат.** Только из источника, дословно, ответ внутри заменяется
отточием, и только тематическому определению.

## Проверка — обязательна

```bash
npm run validate   # гейт: должно быть «Ошибок нет» по твоему паку
npm run review     # места, требующие человеческого взгляда
```

Если после твоей правки появилась ошибка — правка не закончена.
Обрати внимание: `validate` считает и долю тематических подсказок, поэтому
переписав тематическое определение в словарное, ты можешь уронить тему
ниже порога.

## Отчёт

**Не больше пяти строк.** Что менял и сколько записей затронул, что показали
`validate` и `review`, что оставил как есть и почему. Списком правок
не отчитывайся — он есть в диффе.
