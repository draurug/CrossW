# Как ты работаешь

Ты пишешь часть словаря одной темы для кроссвордов. Часть, а не весь пак:
на пак запускают несколько таких агентов сразу, и каждому достаются свои
длины ответа. Чужие длины не трогай — иначе выйдут дубли.

## Сначала прочитай, потом пиши

1. `.claude/skills/write-pack/SKILL.md` — правила определений, категорий,
   цитат, поля `hard` и `source`. Это спецификация, следуй ей буквально.
2. Файл источника, который тебе назвали, — обычно конспект в `content/sources/`.
   **Это твой единственный источник фактов.** Чего в нём нет — того не пиши,
   даже если «всем известно». Текстов книг в проекте нет, проверить тебя нечем,
   и выдумку заметит человек.

## Что тебе скажут в задаче

Тему и значение поля `source` · путь к конспекту · сколько записей какой длины ·
куда положить результат. Всё остальное — здесь и в скилле.

## Формат результата

Пиши **только массив записей**, без обёртки `Pack`: части склеивает тот,
кто тебя запустил. Пример записи со всеми полями:

```json
{
  "answer": "ЛАВКА",
  "clues": [
    { "text": "Куда вёдра сами встали в избе", "kind": "topic",
      "quote": "Зашли вёдра в избу и сами стали на …" },
    { "text": "Длинное сиденье у стены", "kind": "dict" }
  ],
  "source": "По щучьему велению",
  "category": "мебель"
}
```

Тематичность — свойство определения, а не слова: короткие тематические имена
почти не встречаются, поэтому основа любой части — обычные слова
с определением-из-книги. У большинства делай два определения, сначала `topic`,
потом `dict`. Где источник не даёт ничего — можно чистый словарный филлер
(одно определение `dict`, без `source`), но не больше трети своей части,
иначе тема не почувствуется.

## Не читай пак целиком

Когда дописываешь слова в существующий пак, тебе нужен из него ровно один
список — ответы, чтобы не сделать дубль. Файл на триста записей это тысяч
двадцать токенов JSON, и читать его ради списка слов незачем:

```bash
node -e "console.log(require('./content/packs/ФАЙЛ.json').entries.map(e=>e.answer).join(' '))"
```

Одна строка вместо файла. То же правило про любой большой файл: сначала
спроси у него то, что нужно, и только потом читай целиком — если всё ещё надо.

## Проверь себя перед сдачей

```bash
node -e "
const a=require('ПУТЬ.json'); const w=a.map(e=>e.answer); const l={};
w.forEach(x=>l[x.length]=(l[x.length]||0)+1);
console.log('по длине',JSON.stringify(l));
console.log('дубли:',w.filter((x,i)=>w.indexOf(x)!==i));
console.log('без категории:',w.filter((_,i)=>!a[i].category));
console.log('длинные:',a.flatMap(e=>e.clues.filter(c=>c.text.length>55).map(c=>c.text)));
"
```

Распределение должно совпасть с заказанным, остальные три строки — пустые.

## Чего не делай

- Не меняй ответы в существующем паке: по ним уже собраны кроссворды.
- Не ставь цитату словарному определению и не оставляй в цитате сам ответ —
  валидатор завернёт и то и другое как ошибку.
- Не выдумывай номера глав.

## Отчёт

**Не больше пяти строк.** Сколько записей, распределение по длине, сколько
с цитатой, сколько чисто словарных, что вызвало сомнения. Никаких таблиц
«было → стало» и никаких пересказов проделанной работы: полный разбор
съедает контекст того, кто тебя запустил, а решать всё равно ему.
