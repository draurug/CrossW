# Тематический пак CrossW

Пак — это словарь одной темы: слова с определениями, из которых генератор собирает
кроссворды. Лежит в `content/packs/<тема>.json`, типы — в `src/core/model.ts`
(`Pack`, `PackEntry`, `PackClue`).

## Главный принцип

**Тематичность — свойство определения, а не слова.**

ТРАМВАЙ — обычное слово. «Транспорт, обезглавивший Берлиоза» делает его частью
«Мастера и Маргариты».

Без этого приёма тема невозможна: сетку нечем заполнить, если брать только имена
собственные — коротких тематических слов почти не бывает, а в сетке таких слотов
больше половины. Поэтому **обычные слова с определением-из-книги — основа пака,
а не второй сорт.**

Три вида записей живут рядом:

```
ВОЛАНД → «Профессор чёрной магии»    только topic: вне книги слова нет
МАСЛО  → «Что разлила Аннушка»       topic у обычного слова
МАСЛО  → «Продукт из сливок»         dict у того же слова
ОКНО   → «Проём в стене»             только dict: словарный филлер
```

У большинства обычных слов должны быть **оба** определения: сначала `topic`,
потом `dict`. Тогда одно слово годится и в тематический кроссворд, и в нейтральный.

## Сколько слов и какой длины

150–200 записей. Распределение по длине — требование заполняемости, не пожелание:
в сетке больше половины слотов на 3–5 букв, и если коротких слов мало, генератор
сетку не соберёт.

| Длина ответа | 3 | 4 | 5 | 6 | 7 | 8–11 |
|---|---|---|---|---|---|---|
| Минимум записей | 22 | 32 | 38 | 34 | 22 | 25 |

Короткие слова почти всегда обычные: КОТ, БАЛ, СОН, ЛУНА, ПЛАЩ, НОЖ, ВИНО.
Им и нужны определения-из-книги.

## Правила определений

1. **2–4 слова, до 55 символов.** Валидатор предупреждает о длинных.
2. **Определение читается как связная фраза, ответом на которую служит слово в
   именительном падеже единственного числа.** Никаких обрубков и рассогласований:
   - плохо: ЗНАК → «Он был четырех, на клочке бумаги»
   - хорошо: ЗНАК → «Метка четверых на клочке бумаги»
   - плохо: ЗЕРНО → «Пять апельсиновых в конверте» (ответ в единственном, определение во множественном)
   - хорошо: ЗЕРНО → «Апельсиновое, в конверте с угрозой»
   - плохо: НАПОЛЕОН → «Чьи гипсовые бюсты бил вор» («чьи» вместо подлежащего)
   - хорошо: НАПОЛЕОН → «Его бюсты разбивал вор»
3. **Никаких однокоренных с ответом.** Валидатор ловит вхождение начала ответа
   в текст определения — МАСЛО → «Масло, которое разлила Аннушка» будет отвергнуто.
4. **Не синоним, а функция, признак или контекст.** ПРИМУС → «Что починял кот
   Бегемот», а не «Нагревательный прибор».
5. **Однозначность внутри темы.** По определению должно восстанавливаться ровно одно
   слово из этого пака. ВОЛАНД → «Иностранец в Москве» негодно: подходит вся свита.
6. **Факт, а не пересказ.** БЕЗДОМНЫЙ → «Поэт из МАССОЛИТа», а не «Герой, который
   меняется по ходу романа».
7. **Спойлеры развязки помечаются `difficulty: "hard"`** и в лёгкие кроссворды не
   попадают. События первых глав спойлером не считаются.
8. **Безопасно для детей.** Из книги берутся факты, а не натурализм.
9. **Ответы заглавными, Ё сведена к Е.** ЁЖ пишется ЕЖ. Только существительные
   в именительном падеже единственного числа.
10. **Ни одного дубля:** каждый ответ встречается в паке один раз.

## Поле `source`

Обязательно у каждой записи с тематическим определением: «МиМ, гл. 3»,
«Собака Баскервилей», «12 стульев, Васюки». Словарному определению источник
не нужен — словарное значение не спорно.

**Номера глав не выдумывай.** Не уверен — пиши название произведения без номера.

## Поле `hard`

`hard: true` означает «слово для того, кто читал внимательно». Такие записи
генератор не берёт в лёгкие кроссворды.

Критерий — один вопрос: **узнает ли это человек, прочитавший книгу один раз
и без конспекта?**

Ставим:
- второстепенным именам собственным: МОРСТЕН, АФРАНИЙ, ИЗНУРЕНКОВ, БЕЗЕНЧУК;
- редким деталям: ЦЕКУБА, СТАРСОБЕС, ГАМБС;
- обычным словам, которые опознаются только через мелкую деталь: ЖЕМЧУЖИНА,
  если она узнаётся лишь через Мэри Морстен.

Не ставим:
- знаменитым именам: ВОЛАНД, БЕГЕМОТ, ХОЛМС, ВАТСОН, ОСТАП, ЭЛЛОЧКА;
- обычным словам с понятным определением: КЕБ, ГИПС, ТРУБКА, СТУЛ. **Дело не
  в редкости слова и не в его длине;**
- записям с одним словарным определением — они общедоступны по определению.

Ориентир: помеченных выходит 30–60 записей на пак. Меньше десяти или больше
сотни — критерий применён неверно.

## Поле `category`

Первая ступень подсказки: игрок нажимает кнопку и узнаёт, что за слово он ищет,
не получая ни одной буквы. **Обязательно у каждой записи** — валидатор ругается
на отсутствие.

- Два-три слова, строчными, до 30 символов: «предмет одежды», «персонаж», «место»,
  «животное», «часть тела», «профессия», «документ», «еда», «оружие», «транспорт».
- **Род, а не синоним.** ТРУБКА → «предмет курильщика» годится, «курительная
  трубка» нет.
- **Не содержит корня ответа** — валидатор отвергает: СОБАКА → «крупная собака».
- **Одинаковые вещи называй одинаково.** Не «человек», «личность» и «персона»
  в трёх местах. Хорошо, если пак укладывается в 20–30 разных категорий; больше
  сорока — признак, что близкие роды не сведены.
- Имена собственные различай по типу: человек — «персонаж», кличка животного —
  «животное», город — «город», улица — «улица», организация — «организация».

### Омонимы: категория у определения

У `PackClue` тоже есть `category`, и она перебивает общую. Нужна там, где
определения одной записи про разные роды вещей:

```json
{
  "answer": "ЯРД",
  "category": "единица измерения",
  "clues": [
    { "text": "Скотленд-..., служба Лестрейда", "kind": "topic", "category": "учреждение" },
    { "text": "Мера длины в три фута", "kind": "dict" }
  ]
}
```
Без этого подсказка врёт: определение про полицию, а категория про меру длины.

Проверяй такие места сам: у записи два определения — об одном ли роде вещей они?
Расхождение бывает у ФАВОРИТА (скакун против любимца публики), БЕГЕМОТА (кот
против зверя), ПУДЕЛЯ (набалдашник трости против собаки).

Но и не переусердствуй: у ЛЕНТЫ из «Пёстрой ленты» по разгадке змея, а категория
«животное» выдала бы развязку — тут правильнее оставить «предмет обихода».

## Чего делать нельзя

**Не выдумывай факты.** Текстов книг в проекте нет и по политике `docs/spec.md` §8
быть не должно, поэтому проверить тебя нечем. Не уверен, что деталь есть в тексте —
не пиши. Лучше 150 записей, за которые ручаешься, чем 200 с выдумками: их читает
человек и замечает.

**Правишь существующий пак — не меняй ответы.** По ним уже сгенерированы кроссворды,
и смена ответа ломает контент. Меняй тексты определений и добавляй поля.

## Проверка

```bash
npm run validate    # ошибки и предупреждения: гейт, без него публиковать нельзя
npm run review      # места, требующие человеческого взгляда
```

`validate` должен показать «Ошибок нет» по твоему паку. `review` выпишет
повисшие зачины, слишком длинные определения и разнобой в категориях.

Проверка на омонимы в `review` не входит: она давала 250 ложных срабатываний
на 588 записей, потому что у ТИСА и ЛУПЫ оба определения про одно и то же.
Расхождение категорий надо смотреть глазами — см. раздел про омонимы выше.

Собственная проверка распределения по длине:

```bash
node -e "
const p=require('./content/packs/ФАЙЛ.json');
const a=p.entries.map(e=>e.answer); const l={};
a.forEach(w=>l[w.length]=(l[w.length]||0)+1);
console.log('всего',a.length,'| по длине',JSON.stringify(l));
console.log('дубли:',a.filter((w,i)=>a.indexOf(w)!==i));
console.log('hard:',p.entries.filter(e=>e.hard).length);
"
```

## Новая тема — три файла, не один

Пак сам по себе не заработает. Нужны:

1. `content/packs/<тема>.json` — этот пак;
2. запись темы в `content/topics.json` — id, slug, название, описание, `kind`;
3. три названия кроссвордов в `TITLES` в `tools/gen.ts`, под id пака.

Без третьего пункта генератор молча пропустит тему со строчкой
«пропущен: в TITLES нет названий».

Имена файлов и slug — настоящие английские названия, а не транслитерация:
`twelve-chairs`, а не `dvenadtsat-stulyev`.

Дальше: `npm run refresh` соберёт сетки, скомпилирует контент и проверит его.
